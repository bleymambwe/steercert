    steercert.two_clock¶

    Two-clock analysis for diffusion (and autoregressive) language models.

    In an absorbing-state (masked) diffusion LM every intervention site has two time coordinates: depth l and denoising step t. A committed token is frozen, so a probe at step t reads evidence that has already been committed, while a write at step t can only act through positions that are still masked. Read information therefore tends to rise along the denoising clock while write leverage falls. Autoregressive generation is the special case where positions are unmasked left to right.

    This module provides:

    • :class:Lattice, a container for read and write measurements on the (depth, step) grid with the falsifier checks F1 and F2;
    • :func:shape_gap and :func:counting_baseline, which test whether a controllability curve carries attribute-specific structure or is explained by the shrinking set of writable positions alone (falsifier F5);
    • the exact closed-form construction (:func:make_schedule, :func:analytic_read_auc, :func:analytic_write_norm) in which the read and write directions are orthogonal at every step.

    Lattice dataclass ¶

    Read and write measurements on a (depth, denoising step) grid.

    Attributes:

    Name Type Description
    read ndarray

    (n_depths, n_steps) decodability, for example probe AUC.
    write ndarray

    (n_depths, n_steps) absolute write leverage, for example |g_bar|.
    steps ndarray

    Denoising progress for each column, increasing (0 = fully masked).
    depths tuple

    Labels for each row.

    write_decreasing(tolerance=0.0) ¶

    F1 check per depth: write leverage never rises along the denoising clock.

    clocks_dissociated() ¶

    F2 check per depth: decodability and leverage peak at different steps.

    joint_optimum(read_weight=0.5) ¶

    Step that maximises a weighted geometric mean of normalised read and write.

    Schedule dataclass ¶

    An absorbing-diffusion unmasking order over read and write positions.

    normalise_curve(values) ¶

    Divide a non-negative curve by its maximum (zero curves are returned unchanged).

    shape_gap(curve, baseline) ¶

    Largest difference between two curves after each is peak-normalised.

    A small gap means the measured controllability curve has the same shape as the content-free baseline, so its decay is explained by counting alone.

    counting_baseline(writable_counts) ¶

    Content-free write-leverage curve from the number of writable positions.

    If each still-masked payload position contributes an equal, independent gradient component, the mean-gradient norm scales as the square root of the number of writable positions. Schedule-aware steering methods should beat this curve, which costs one count per step and no training.

    make_schedule(n_read, n_write, seed=0, order='random') ¶

    Build a schedule; order='identity' is the autoregressive case.

    analytic_read_auc(schedule, step, kappa, sigma) ¶

    Population AUC of the optimal linear readout of committed evidence.

    With m committed read positions the pooled statistic has separation d' = kappa sqrt(m) / sigma and AUC = Phi(sqrt(2) d').

    analytic_write_norm(schedule, step, gamma) ¶

    Mean-gradient norm at step; proportional to sqrt(masked write positions).

    remask_recoverable(schedule, step, n_remask) ¶

    Write positions made writable again by remasking n_remask recent write commits.

    Read commitments are untouched, so remasking raises controllability at unchanged decodability. The same operation underlies remask-based safety defences and remask-based attacks.
